## 5. 障害記録と対応

試験中に検出した不具合と、その対応・再確認の記録。

### 障害 No.1 — 株価取得が全件不採用になり、購入が成立しない

| 項目 | 内容 |
| --- | --- |
| 検出 | TC-SY-04（初回実行時） |
| 現象 | 買い候補 3 銘柄すべてが「株価を取得できなかったため購入を見送りました」となり、1 株も約定しなかった。再試行に約 17 分を要した |
| 原因 | Gemini に「JSON のみで出力せよ」と指示すると Web 検索を実行せず、モデル内部の知識のみで回答する。この応答は FR-08-02（検索の裏付けがない回答は採用しない）により全件不採用となっていた |
| 切り分け | TC-EX-02（JSON 指定 → 検索なし）と TC-EX-03（自然文 → 検索あり）を比較して原因を特定。TC-EX-04 で `google_search_retrieval` による強制検索が当該モデルで利用できないことも確認 |
| 対応 | 株価取得を 2 段に分割（① 自然文で検索させる ② 検索なしの呼び出しで JSON に整形）。あわせてリトライ間隔を短縮 |
| 再確認 | TC-SY-02（3 銘柄 29.9 秒・全件採用）、TC-SY-04（2 銘柄の約定成立） |
| 結果 | **解消（OK）** |

### 障害 No.2 — 全株売却した取引が「一部売却」と表示される

| 項目 | 内容 |
| --- | --- |
| 検出 | 利用者からの指摘（実現損益画面で、保有していないさくらインターネットが「一部売却」と表示されていた） |
| 現象 | 100 株保有を 100 株売却した取引（保有は正しく 0 件）の区分が「一部売却」と表示された |
| 原因 | AI が返す `action` は売買の**理由**（`take_profit` / `stop_loss` / `rebalance`）であるにもかかわらず、`rebalance` に「一部売却」という**数量**のラベルを割り当てていた。理由と数量という独立した 2 つの軸を 1 つの列に混在させていた設計不備。データ自体（保有 0 件・実現損益 0 円）は正しかった |
| 対応 | ① `trades.shares_after`（約定後の保有株数）を追加し、数量ラベルを `shares_after` から導出 ② `rebalance` のラベルを「方針変更」に修正 ③ 全株判定を `shares_after === 0` に変更 ④ 既存 6 件をマイグレーションで自動補完 |
| 再確認 | TC-TE-09 / TC-TE-10 / TC-TE-11（自動テストとして追加）、TC-MG-01（既存データの補完） |
| 結果 | **解消（OK）**。該当取引は「方針変更 / 全株売却」と表示されることを確認 |
