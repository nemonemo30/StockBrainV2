# Stock Brain 要件定義書

| 項目 | 内容 |
| --- | --- |
| システム名 | Stock Brain |
| 版 | 1.0 |
| 作成日 | 2026-09-19 |
| 最終更新 | 2026-10-07（4判断化・デイトレ・株価の対象日関門を反映） |
| 対象範囲 | Web 画面、定期実行バッチ、外部 AI 連携 |

---

## 1. システムの目的

生成 AI（Google Gemini）に日本株のポートフォリオ運用を判断させ、その結果を記録・可視化する
**投資シミュレーションゲーム**である。

株価は実際の市場データを参照する（実環境）が、**証券会社への発注は一切行わない**。
損益は本システム内の計算上のものである。

## 2. スコープ

### 2.1 本システムに含むも

- 東証上場銘柄マスタの取り込み
- 株価の自動取得（外部 AI 経由）
- 機械的な損切り・利確と、AI による厳しい新規の検証・約定処理
- ポートフォリオ（保有銘柄・現金・評価損益・実現損益）の管理と画面表示
- 予算（資金）の登録
- 管理者 1 名によるログイン認証

### 2.2 本システムに含まないもの

| 項目 | 理由 |
| --- | --- |
| 証券会社への実発注 | シミュレーションのため |
| リアルタイム株価（ザラ場中の現在値） | 採用したデータ取得方式では直近営業日の終値が中心となる（→ [制約 C-02](#71-制約事項)） |
| 売買手数料・税金の計算 | 初版では対象外 |
| 複数ユーザー・複数ポートフォリオ | 管理者 1 名／口座 1 つを前提とする |
| ユーザー登録画面・パスワード再発行 | 管理者はサーバ側で作成する |
| 信用取引・空売り・ナンピン指示 | 現物の買いと売りのみ |

## 3. 利用者と役割

| 利用者 | 役割 |
| --- | --- |
| 管理者 | ログインして全画面を閲覧する。予算（資金）を登録する |
| Gemini（外部 AI） | 株価の調査と売買判断を行う。システム利用者ではなく外部 IF |

## 4. 機能要件

### 4.1 認証（FR-01 系）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-01-01 | ログイン画面でメールアドレスとパスワードによる認証ができる | 必須 |
| FR-01-02 | 認証に失敗した場合、画面にエラーを表示し、ログインさせない | 必須 |
| FR-01-03 | 未認証の利用者が認証必須画面にアクセスした場合、ログイン画面へ遷移させる | 必須 |
| FR-01-04 | 認証済みの利用者がログイン画面にアクセスした場合、トップ相当画面へ遷移させる | 必須 |
| FR-01-05 | ログアウトできる。ログアウト後はログイン画面へ遷移する | 必須 |
| FR-01-06 | 「ログインしたままにする」を選択できる | 任意 |

### 4.2 スプラッシュ画面（FR-02 系）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-02-01 | **ログインに成功したとき**に「Stock Brain」の文字を表示する | 必須 |
| FR-02-02 | 表示から **2 秒後**に自動でトップ画面へ遷移する | 必須 |
| FR-02-03 | JavaScript が無効な環境でも 2 秒後に遷移する | 必須 |
| FR-02-04 | ブラウザの戻る操作でスプラッシュ画面に戻らない | 任意 |

### 4.3 トップ画面（FR-03 系）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-03-01 | 現在保有している銘柄の一覧を表示する | 必須 |
| FR-03-02 | 銘柄ごとに「何株保有しているか」を表示する | 必須 |
| FR-03-03 | 銘柄ごとに「現在の評価損益がいくらか」を金額と率で表示する | 必須 |
| FR-03-04 | 取得単価・現在株価・評価額を表示する | 必須 |
| FR-03-05 | ポートフォリオ全体の評価損益・評価額・取得金額・現金残高・総資産・累計実現損益・トータルリターンを表示する | 必須 |
| FR-03-06 | 株価を取得できていない銘柄はその旨を明示し、取得単価（簿価）で評価する | 必須 |
| FR-03-07 | 直近の約定履歴と、AI の判断理由を表示する | 任意 |
| FR-03-08 | 直近のバッチ実行状況（成否・株価取得件数・売買件数）を表示する | 任意 |
| FR-03-09 | 保有銘柄が 0 件の場合は、その旨と次に行う操作を案内する | 任意 |

### 4.4 定期実行バッチ（FR-04 系）

現行（2026-10-01〜）の実行時刻は [運用メモ](../04_運用/運用メモ_共有用.md)。  
判断は 9:05 / 11:00 / 13:00 / 15:00 の 4 回（いずれも `stockbrain:run morning`）。12:00 の `noon` は使わない。11:35 は株価だけ。16:00 は評価記録。

| ID | 時刻 | 要件 | 優先度 |
| --- | --- | --- | --- |
| FR-04-01 | 判断セッション | 保有している株の現在の株価を取得する | 必須 |
| FR-04-02 | 判断セッション | 利確・損切りを実施する。不要であれば何もしない | 必須 |
| FR-04-03 | 判断セッション | 残っている予算の範囲内で、購入したい銘柄があれば購入する | 必須 |
| FR-04-04 | 11:00 | FR-04-01 と同じ（旧 12:00。2026-10-01 に 11:00 へ変更） | 必須 |
| FR-04-05 | 11:00 | FR-04-02 と同じ | 必須 |
| FR-04-06 | 11:00 | FR-04-03 と同じ | 必須 |
| FR-04-11 | 13:00 / 15:00 | FR-04-01〜03 と同じ | 必須 |
| FR-04-12 | 11:35 | 保有株の株価だけ更新する。売買も評価記録もしない | 必須 |
| FR-04-07 | 16:00 | 保有している株の現在の株価を取得する | 必須 |
| FR-04-08 | 16:00 | 評価損益等を計算し、日次の記録として保存する | 必須 |
| FR-04-09 | 全 | 各セッションの実行結果（成否・件数・AI の応答）をログとして保存する | 必須 |
| FR-04-10 | 全 | 手動実行および約定を伴わない試験実行（dry-run）ができる | 任意 |

### 4.5 売買判断（FR-05 系）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-05-01 | **損切り・利確・トレーリング・時間切れはコード（DayTradeEngine）が機械的に行う**。Gemini に延期させない | 必須 |
| FR-05-02 | 新規購入する銘柄は Gemini が選ぶ（厳しいセットアップのみ）。株数はアプリがリスクに合わせて切る | 必須 |
| FR-05-03 | Gemini の判断理由を保存し、画面で確認できる | 必須 |
| FR-05-04 | 売却は全株・一部のいずれも指示できる | 必須 |

### 4.6 購入の成立条件（FR-06 系）

Gemini が購入を指示しても、以下をすべて満たさない場合は約定させない。

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-06-01 | 指示された銘柄コードが**銘柄マスタ（DB）に存在する**こと | 必須 |
| FR-06-02 | その銘柄が売買対象区分（内国株式）であること | 必須 |
| FR-06-03 | その銘柄の**株価取得が成功している**こと | 必須 |
| FR-06-04 | 約定代金が現金残高以内であること。超える場合は買える単元数まで自動的に減らす | 必須 |
| FR-06-05 | 株数は売買単位（100 株）の倍数であること | 必須 |
| FR-06-06 | 成立しなかった場合は理由を記録し、実行ログに残すこと | 必須 |

### 4.7 銘柄マスタ（FR-07 系）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-07-01 | 東証上場銘柄一覧（JPX 公開の Excel ファイル）を DB に取り込める | 必須 |
| FR-07-02 | 内国株式（プライム・スタンダード・グロース）を売買対象、それ以外（ETF・REIT 等）を対象外として区別する | 必須 |
| FR-07-03 | 再取り込み時は銘柄コードをキーに更新する（重複を作らない） | 必須 |

### 4.8 株価取得（FR-08 系）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-08-01 | 外部 AI 経由で株価を取得する | 必須 |
| FR-08-02 | **検索の裏付けがない回答（AI の記憶による回答）は採用しない** | 必須 |
| FR-08-03 | 直近に採用した株価から一定割合を超えて乖離した値は採用しない | 必須 |
| FR-08-04 | 採用・不採用の結果と理由、引用元を記録する | 必須 |
| FR-08-05 | 取得に失敗した銘柄は売買を見送る（誤った株価で約定させない） | 必須 |
| FR-08-06 | 対象日の年が確定できない数字、前年同日の記事、ニュース／25日線一覧の数字は現在値として採用しない | 必須 |

### 4.9 予算管理（FR-09 系）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-09-01 | 管理者画面から予算を登録できる | 必須 |
| FR-09-02 | 初期資金は 100 万円とし、**DB で管理する** | 必須 |
| FR-09-03 | 入金を登録すると現金残高（買付余力）が増える | 必須 |
| FR-09-04 | 出金を登録すると現金残高が減る。現金残高を超える出金はできない | 必須 |
| FR-09-05 | 予算の登録はトータルリターンの分母（投入元本）に反映される | 必須 |
| FR-09-06 | 登録履歴（日時・区分・金額・登録後残高・メモ・登録者）を保持し、画面で確認できる | 必須 |
| FR-09-07 | 現在の資金状況（投入元本・現金残高・評価額・総資産・評価損益・トータルリターン）を確認できる | 必須 |

### 4.10 実現損益画面（FR-10 系）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-10-01 | 確定した損益を、**いつ利確／損切りしたか**と**いくらだったか**が分かる形で一覧表示する | 必須 |
| FR-10-02 | 画面上部に**今月の合計**と**今年の合計**を表示する | 必須 |
| FR-10-03 | 上部に、より短い期間（今日・直近 7 日）および全期間の合計も表示する | 任意 |
| FR-10-04 | 集計期間を選択できる（今日／直近 7 日／直近 30 日／今月／先月／今年／全期間） | 必須 |
| FR-10-05 | **実現損益に表示されている銘柄**を選択して絞り込める（セレクトボックス） | 必須 |
| FR-10-06 | 表示件数は **20 件**とし、**ページング**を行う | 必須 |
| FR-10-07 | ページを移動しても期間・銘柄の絞り込み条件が維持される | 必須 |
| FR-10-08 | 銘柄で絞り込んだ場合、上部の期間別合計もその銘柄のみの集計になる | 任意 |
| FR-10-09 | 一覧に、取得単価・売却単価・損益率・AI の判断理由を表示する | 任意 |
| FR-10-10 | 件数・利確／損切りの内訳・勝率を表示する | 任意 |
| FR-10-11 | 買い注文は実現損益の対象外とする | 必須 |
| FR-10-12 | 全株売却と一部売却を区別して表示する | 必須 |

## 5. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | 稼働 | 定期実行は平日のみ。祝日判定は行わない（→ [C-05](#71-制約事項)） |
| NFR-02 | 性能 | 1 セッションの実行時間は 5 分以内を目安とする。株価取得は 5 銘柄あたり約 30 秒 |
| NFR-03 | 性能 | 画面応答は 1 秒以内を目安とする |
| NFR-04 | 可用性 | 外部 AI の障害・不正応答時も処理を中断せず、その銘柄の売買を見送って続行する |
| NFR-05 | 整合性 | 約定・予算登録は DB トランザクションで行い、現金残高と履歴が矛盾しないこと |
| NFR-06 | 監査性 | 株価の採否、AI の判断内容、約定、予算の増減をすべて履歴として残すこと |
| NFR-07 | 機密 | API キー・認証情報は `.env` で管理し、バージョン管理対象に含めないこと |
| NFR-08 | 保守 | 株価取得処理は差し替え可能な単位に分離すること（→ 証券会社 API への移行を想定） |
| NFR-09 | 利便 | 画面は日本語表示、金額は円・3 桁区切り、損益は符号つきで表示すること |
| NFR-10 | 利便 | 損益の色は国内証券の慣習に合わせ、プラスを赤、マイナスを青とすること |
| NFR-11 | 利便 | スマートフォン幅（約 400px）でも表示が崩れないこと |
| NFR-12 | 品質 | 金額計算と購入条件の検証は自動テストで担保すること |

| ID | 前提 |
| --- | --- |
| P-01 | 実行環境に PHP 8.2 以上、Composer、SQLite が導入されていること |

## 7. 制約事項・リスク

### 7.1 制約事項

| ID | 制約 | 影響 | 対応 |
| --- | --- | --- | --- |
| C-01 | 株価は外部 AI の検索結果に依存し、証券会社の公式 API を用いない | 株価の精度・鮮度に限界がある | 検索の裏付けと乖離率の二重チェックで誤値を排除（FR-08-02、FR-08-03） |
| C-02 | 取得できる株価は検索結果に依存する。ザラ場中の板は見ない | 判断セッションでも、銘柄ページと違う数字や前日終値で約定しうる | 対象日の年とページ種別を関門にする（FR-08-06）。リアルタイム化は株価取得の差し替え（NFR-08） |
| C-03 | 外部 AI は同じ入力でも異なる判断を返す | 実行結果は再現しない | ゲームの性質として許容。判断内容を全件記録して追跡可能にする |
| C-04 | 売買手数料・税金を考慮しない | 損益が実際の運用より有利に出る | 初版では対象外 |
| C-05 | 臨時休場（台風など）と 2028 年以降の祝日は未登録 | その日は通常の開場日として動く | JPX 休業日（2026・2027）と土日は `TradingCalendar` でスキップ済み |
| C-06 | 株価取得に失敗した銘柄は簿価で評価する | 評価損益が実勢と乖離する | 画面に「取得失敗」を明示する（FR-03-06） |

### 7.2 リスク

| ID | リスク | 対策 |
| --- | --- | --- |
| R-01 | 外部 AI が存在しない銘柄コードを返す | 銘柄マスタとの照合で弾く（FR-06-01） |
| R-02 | 外部 AI が実在しない株価を返す（幻覚） | 検索の裏付けと乖離率で弾く（FR-08-02、FR-08-03） |
| R-03 | 外部 AI が現金残高を超える購入を指示する | 買える単元数まで自動的に減らす（FR-06-04） |
| R-04 | 外部 AI の API 障害・タイムアウト | リトライ後、当該処理を見送って続行する（NFR-04） |
| R-05 | API キーの漏洩 | `.env` 管理、バージョン管理除外（NFR-07）。漏洩時はキーを再発行する |

## 8. 用語

| 用語 | 意味 |
| --- | --- |
| セッション | 1 回分のバッチ。現行は判断 4 回（`morning`）＋株価更新（`quotes`）＋引け後（`close`） |
| 評価損益 | 保有中の銘柄の含み損益。`(現在株価 − 取得単価) × 株数` |
| 実現損益 | 売却によって確定した損益。`(売却単価 − 取得単価) × 売却株数` |
| 投入元本 | 初期資金と、その後の入金・出金を合算した元手。トータルリターンの分母 |
| 総資産 | `現金残高 + 保有銘柄の評価額` |
| グラウンディング | 外部 AI が Web 検索を実行し、その結果を根拠として回答すること |
| 単元株 | 売買の最小単位。国内株式は 100 株 |
| 利確 | 利益が出ている状態での売却 |
| 損切り | 損失が出ている状態での売却 |
