## 3. 外部 API インターフェース（IF-X）

### 3.1 共通仕様

| 項目 | 内容 |
| --- | --- |
| 接続先 | `https://generativelanguage.googleapis.com/v1beta` |
| エンドポイント | `POST /models/{model}:generateContent` |
| モデル | `gemini-3.5-flash`（`GEMINI_MODEL` で変更可） |
| 認証 | リクエストヘッダ `x-goog-api-key: {GEMINI_API_KEY}` |
| Content-Type | `application/json` |
| タイムアウト | 120 秒（`GEMINI_TIMEOUT`） |
| リトライ | 2 回・間隔 1.5 秒（例外送出はせず、失敗レスポンスを返す） |
| 実装 | `app/Services/Gemini/GeminiClient.php` |

リクエストボディ（共通形）

```json
{
  "contents": [
    { "role": "user", "parts": [{ "text": "<プロンプト>" }] }
  ],
  "tools": [{ "google_search": {} }],
  "systemInstruction": { "parts": [{ "text": "<システム指示>" }] }
}
```

- `tools` は Google 検索グラウンディングを使う場合のみ付与する。
- `systemInstruction` は指定した場合のみ付与する。

レスポンスから参照する項目

| JSON パス | 用途 |
| --- | --- |
| `candidates[0].content.parts[*].text` | 本文（連結して使用） |
| `candidates[0].groundingMetadata.webSearchQueries` | 実行された検索クエリ。検索の裏付け判定に使用 |
| `candidates[0].groundingMetadata.groundingChunks[*].web.title` | 引用元のタイトル |
| `candidates[0].groundingMetadata.groundingChunks[*].web.uri` | 引用元の URI |
| `error.message` | エラー時のメッセージ |

エラー処理

| 条件 | 扱い |
| --- | --- |
| HTTP ステータスが失敗 | `RuntimeException`（`Gemini API エラー (HTTP {code}): {message}`） |
| `webSearchQueries` と `groundingChunks` がいずれも空 | 「検索の裏付けなし」と判定（IF-X-01 のみ） |
| 本文から JSON を取り出せない | `JsonException` |

本文の JSON 抽出は、` ```json ` フェンスの除去と、最初の `{`／`[` から最後の `}`／`]` までの
切り出しに対応する。

### IF-X-01 株価調査（1 段目）

| 項目 | 内容 |
| --- | --- |
| 呼び出し元 | `StockPriceFetcher::research()` |
| `tools` | `google_search` **あり** |
| 出力形式の指定 | **しない**（指定すると検索が実行されないため） |
| 1 回の対象銘柄数 | 最大 5 件 |

送信内容（要旨）

```
東証上場の次の銘柄について、直近の株価を調べてください。
ザラ場中であれば現在値、市場が閉じていれば直近営業日の終値です。

対象: {銘柄名}（{コード}）、…

銘柄ごとに「銘柄コード・株価（円）・その株価の日付・参照したサイト名」を書いてください。
株価分割を反映した現在の株価でお願いします。
調べても確かな数値が見つからない銘柄は「不明」と書いてください。推測した数値は書かないでください。
```

受信内容: 自然文（銘柄ごとの株価・日付・情報源）

| 判定 | 処理 |
| --- | --- |
| 検索の裏付けあり | 2 段目へ渡す |
| 検索の裏付けなし（1 回目） | 「必ず Google 検索で最新の株価ページを確認してから回答してください。」を追記して再試行 |
| 検索の裏付けなし（2 回目） | 取得失敗として扱い、対象銘柄すべてを不採用にする |

### IF-X-02 JSON 整形（2 段目）

| 項目 | 内容 |
| --- | --- |
| 呼び出し元 | `StockPriceFetcher::extract()` |
| `tools` | **なし**（検索しない） |

送信内容（要旨）

```
次の文章から、銘柄コードごとの株価を抜き出して JSON 配列にしてください。
--- 文章 ---
{1 段目の回答文}
--- ここまで ---
対象の銘柄コード: {コード, …}

- 文章に書かれている数値だけを使ってください。文章に無い銘柄や「不明」の銘柄は price を null に。
- price は円単位の数値（カンマなし）。
- 出力は JSON 配列のみ。
```

受信内容

```json
[{ "code": "7203", "price": 3025.0, "as_of": "2026-09-18" }]
```

| 項目 | 型 | 説明 |
| --- | --- | --- |
| `code` | string | 銘柄コード。空の要素は破棄 |
| `price` | number \| null | 株価。null・非数値・0 以下は不採用 |
| `as_of` | string | 株価の時点（`price_quotes.as_of_text` に保存） |

### IF-X-03 売買判断

| 項目 | 内容 |
| --- | --- |
| 呼び出し元 | `TradeAdvisor::decide()` |
| `tools` | `google_search` あり（市況・ニュースの確認用） |
| `systemInstruction` | あり（下記） |

システム指示

```
あなたは日本株のポートフォリオを運用するトレーダーです。
与えられた保有状況と現金残高だけを前提に、今このタイミングで取るべき行動を決めます。
根拠のない楽観や、全額を一銘柄に集中させるような判断は避けてください。
出力は指示された JSON のみとし、前後に説明文を付けないでください。
```

送信内容（要旨）

```
現在時刻は {寄り前 9:05 | 前場 11:00 | 後場 13:00 | 引け前 15:00} です。

【現金残高】{金額} 円
【保有銘柄】
- {銘柄名}({コード}) {株数}株 / 取得単価 {単価}円 / 現在株価 {株価} / 評価損益 {金額}円 ({率}%)
…（保有なしの場合は「（保有なし。まだ 1 銘柄も買っていません）」）

1. 保有銘柄それぞれについて、いま売るべきか（利確／損切り）、持ち続けるべきか。
   売る場合は株数を指定（100 株単位、全株・一部いずれも可）。不要なら sells は空配列。
2. 現金残高の範囲内で新規に買いたい銘柄があれば、最大 5 銘柄まで。
   - 東証の内国株式（プライム・スタンダード・グロース）に限る
   - 売買単位は 100 株。株数は 100 の倍数
   - 現金残高を超える金額は約定しない
   - 不要なら buys は空配列
```

受信内容

```json
{
  "sells": [
    { "code": "3778", "shares": 100, "action": "rebalance", "reason": "日銀の追加利上げを警戒し…" }
  ],
  "buys": [
    { "code": "8306", "shares": 100, "reason": "金利上昇局面で資金利ざやの改善が期待できる…" }
  ],
  "comment": "キャッシュ100%の状態から、銀行株とAIテーマの2銘柄に分散投資します。"
}
```

| 項目 | 型 | 必須 | 説明・正規化 |
| --- | --- | --- | --- |
| `sells[].code` | string | ○ | 空なら要素を破棄 |
| `sells[].shares` | integer | ○ | 0 以下なら要素を破棄 |
| `sells[].action` | string | — | `take_profit` / `stop_loss` / `rebalance`。既定 `rebalance` |
| `sells[].reason` | string | — | 判断理由。既定 空文字 |
| `buys[].code` | string | ○ | 空なら要素を破棄 |
| `buys[].shares` | integer | ○ | 0 以下なら要素を破棄 |
| `buys[].reason` | string | — | 判断理由 |
| `comment` | string | — | 今回の方針 |

`buys` は先頭 5 件（`STOCKBRAIN_MAX_BUY_CANDIDATES`）に切り詰める。
取得に失敗した場合は `{sells: [], buys: [], comment: "AI 判断を取得できませんでした: …"}` を返し、
セッションは継続する。

応答は引用元・検索クエリとともに `job_runs.ai_decision` に保存する。

### IF-F-01 東証上場銘柄一覧 取り込み

| 項目 | 内容 |
| --- | --- |
| ファイル名 | `data_j.xlsx` |
| 既定パス | `storage/data_j.xlsx` |
| 提供元 | JPX「東証上場銘柄一覧」 |
| 形式 | Excel（xlsx）、1 シート、1 行目ヘッダー |
| 文字コード | Excel 内部（UTF-8 相当） |
| 読み取りライブラリ | PhpSpreadsheet（`setReadDataOnly(true)`） |

レイアウト

| 列 | 項目名 | 取り込み先 | 変換 |
| --- | --- | --- | --- |
| A | 日付 | `stocks.listing_date` | `YYYYMMDD` → 日付。形式不一致は NULL |
| B | コード | `stocks.code` | 前後空白除去。空なら行をスキップ |
| C | 銘柄名 | `stocks.name` | 前後空白除去。空なら行をスキップ |
| D | 市場・商品区分 | `stocks.market` | 前後空白除去 |
| E | 33業種コード | （未使用） | — |
| F | 33業種区分 | `stocks.sector33` | `-` → NULL |
| G | 17業種コード | （未使用） | — |
| H | 17業種区分 | `stocks.sector17` | `-` → NULL |
| I | 規模コード | （未使用） | — |
| J | 規模区分 | `stocks.scale` | `-` → NULL |

`stocks.tradable` は D 列が売買対象市場区分のいずれかに一致する場合 true。

登録方式: `code` をキーに 500 件単位で `upsert`。
更新対象列は `name` / `market` / `sector33` / `sector17` / `scale` / `tradable` / `listing_date`。

| コマンド | `php artisan stockbrain:run {session} [--dry-run]` |
| 実装 | `App\Console\Commands\RunTradingSession` |

| 引数 / オプション | 必須 | 説明 |
| --- | --- | --- |
| `session` | ○ | `morning` / `noon` / `quotes` / `close` |
| `--dry-run` | — | 売買を実行せず、AI の判断のみ表示する |

| 終了コード | 条件 |
| --- | --- |
| 0 | 正常終了 |
| 1 | `session` が不正、または処理中に例外が発生 |

標準出力: 株価取得の銘柄別結果（OK / NG と理由）、AI の方針、売却・購入の約定／見送り内容、
および現金残高・評価額・総資産・評価損益・累計実現損益・保有銘柄数・株価取得件数の表。

副作用: `job_runs` に 1 行、`price_quotes` に取得件数分。
`quotes` は株価だけ。`morning` / `noon` は約定があれば `trades` / `holdings` / `portfolios`。
`close` は `portfolio_snapshots` を更新。

### スケジュール定義

本番は Lolipop cron（[運用メモ](../04_運用/運用メモ_共有用.md)）。`routes/console.php` は現行では使わない。

| セッション | 本番の実行条件 |
| --- | --- |
| `morning` | 平日 9:05 / 11:00 / 13:00 / 15:00。`cron-morning.php` |
| `quotes` | 平日 11:35。`cron-quotes.php`。売買しない |
| `close` | 平日 16:00。`cron-close.php` |
| `noon` | 本番未使用。`cron-noon.php` は残置 |

## 6. 内部サービスインターフェース（IF-S）

### IF-S-01 StockPriceFetcher

```php
fetch(array $codes, ?JobRun $run = null): Collection<string, PriceQuote>
```

| 項目 | 内容 |
| --- | --- |
| 入力 | `$codes` 銘柄コードの配列（重複・空値は除去）、`$run` 紐づけるジョブ実行 |
| 出力 | 銘柄コードをキーにした `PriceQuote`。**失敗分も含めて全件返す** |
| 副作用 | `price_quotes` に取得結果を保存 |
| 備考 | 5 件ずつに分割して IF-X-01 → IF-X-02 を呼び出す |

`PriceQuote::$price` が `null` の場合は取得失敗。理由は `failure_reason` に入る。

### IF-S-02 TradeAdvisor

```php
decide(Portfolio $portfolio, string $session): array
```

| 項目 | 内容 |
| --- | --- |
| 入力 | `$portfolio` 口座（保有銘柄をロード済み）、`$session` `morning` / `noon`（本番の判断は `morning` を 4 回） |
| 出力 | `['sells' => array, 'buys' => array, 'comment' => string, 'sources' => array, 'search_queries' => array]` |
| 副作用 | なし（呼び出し元が `job_runs.ai_decision` に保存する） |
| 例外 | 送出しない。失敗時は空の判断を返す |

### IF-S-03 TradeExecutor

```php
sell(Portfolio $portfolio, array $sells, ?JobRun $run = null): array
buy(Portfolio $portfolio, array $buys, Collection $quotes, ?JobRun $run = null): array
```

| 項目 | 内容 |
| --- | --- |
| 入力（sell） | 正規化済みの売却指示の配列 |
| 入力（buy） | 正規化済みの購入指示の配列、株価取得結果（IF-S-01 の戻り値） |
| 出力 | `[['code' => string, 'status' => 'executed'\|'skipped', 'message' => string], …]` |
| 副作用 | `trades` / `holdings` / `portfolios.cash` を更新（1 件ごとにトランザクション） |

### IF-S-04 GeminiClient

```php
generate(string $prompt, bool $search = false, ?string $systemInstruction = null): GeminiResponse
```

| 項目 | 内容 |
| --- | --- |
| 入力 | `$prompt` プロンプト、`$search` 検索グラウンディングの有無、`$systemInstruction` システム指示 |
| 出力 | `GeminiResponse`（`text` / `searchQueries` / `sources` / `raw`） |
| 例外 | `RuntimeException`（API キー未設定、HTTP エラー） |

`GeminiResponse` の主なメソッド

| メソッド | 内容 |
| --- | --- |
| `isGrounded(): bool` | 検索クエリまたは引用元が 1 件以上あるか |
| `json(): array` | 本文から JSON を取り出す。取り出せない場合 `JsonException` |
