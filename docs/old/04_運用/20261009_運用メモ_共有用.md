# Stock Brain 運用メモ（共有用）

対象: シミュレーション運用（証券会社への実発注はしない）
更新: 2026-10-09

## 1日の動き

本番は **Lolipop の cron** が PHP ラッパーを直接叩く。  
`routes/console.php` の 9:00 / 12:00 / 16:00（`artisan schedule:run`）は現行では使っていない。

2026-10-01 から判断は 1 日 4 回。12:00 の `noon` は回していない。

| 時刻 | ラッパー | コマンド | 画面ラベル | 内容 |
|---|---|---|---|---|
| 9:05 | `cron-morning.php` | `stockbrain:run morning` | 9:00 寄り前 | 株価取得 → 機械的な損切り・利確・トレール・時間切れ → 厳しい新規だけ |
| 11:00 | `cron-morning.php` | 同じ | 11:00 前場 | 同じ |
| 11:35 | `cron-quotes.php` | `stockbrain:run quotes` | 株価更新 | 保有の株価だけ更新。売買しない。評価の記録もしない |
| 13:00 | `cron-morning.php` | `stockbrain:run morning` | 13:00 後場 | 判断セッション（9:05 と同じ） |
| 15:00 | `cron-morning.php` | 同じ | 15:00 引け前 | 同じ |
| 16:00 | `cron-close.php` | `stockbrain:run close` | 16:00 引け後 | 株価取得 → 評価損益を記録。新規の売買はしない |

`cron-noon.php`（`stockbrain:run noon`）はコードとして残っているが、本番 cron には載せていない。

売りはコードが先に決める。Gemini は検索して、外れても小さく負けられる新規と、根拠切れの売却だけ。実際の株の発注はしない。

保有の株価は Yahoo チャート（`3968.T` など）を先に取る。取れなかった銘柄だけ Gemini 検索。証券会社の注文 API は使わない。Yahoo も株価を見るだけ。

画面のジョブラベルはセッション名ではなく、開始時刻（Asia/Tokyo）で付く。`morning` を 13:00 に流しても「9:00 寄り前」にはならない。

## 土日

- cron は毎日動く（発火する）
- 土日は処理をスキップする
- 株価取得・AI判断・売買はしない
- DB の実行ログ（`job_runs`）も残さない

## 休場（祝日・年末年始など）

- JPX の休業日一覧（2026・2027）をコードに持っている
- 該当日は土日と同じくスキップする（株価取得・AI・売買なし、DB ログなし）
- 対象例: 敬老の日、振替休日、1/2、12/31
- 臨時休場（台風など）は未対応
- 2028年以降のカレンダーは未登録。追加が必要

## ログの場所

| 場所 | 内容 |
|---|---|
| DB `job_runs` | セッションの成否、件数、AI の判断 |
| DB `price_quotes` | 株価の採否と理由 |
| DB `trades` | 約定履歴 |
| 画面 | 直近の実行状況 |
| `docs/05_インシデント/` | 件ごとのフォルダ（報告・リカバリ・テスト記録） |

## 補足

- 土日・東証休業日はコード側でスキップ
- 実取引連携は未実装。将来の拡張対象
- 誤約定の後始末は買い取り消し `stockbrain:void-buy`、売却単価訂正 `stockbrain:correct-sell`。手順はインシデント側
- 保有は最大 10 銘柄。1 銘柄の金額天井は無い。株数は現金と 1% リスクと単元 100 で切る
- 売買は 100 株単位。100 株玉の +5% は半分に割れないので全株利確。既にある端株（例: ラクス残り 50）の全決済だけ例外
- 株価は対象日の年が確定できない数字、前年同日の記事、25日線一覧を採用しない（`QuoteDateGuard`。INC001）。Yahoo・AI どちらもこの関門を通す
- 本番に上げる株価取得の差分は `app/Services/YahooQuoteClient.php`（新規）と `app/Services/StockPriceFetcher.php`。migrate も `.env` も cron も変えない。テストと docs はロリポップに不要
