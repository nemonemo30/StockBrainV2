# Stock Brain 運用メモ（共有用）

対象: シミュレーション運用（証券会社への実発注はしない）
更新: 2026-10-23

## 1日の動き

本番は **Lolipop の cron** が PHP ラッパーを直接叩く。  
`routes/console.php` の 9:00 / 12:00 / 16:00（`artisan schedule:run`）は現行では使っていない。

定時の判断は 1 日 6 回。12:00 の `noon` は回していない。  
10 分ごとの株価更新で機械決済の線を跨いだときだけ、morning を足す。経緯は [06_開発](../06_開発/20261023_定時外morning.md)。

| 時刻 | ラッパー | コマンド | 画面ラベル | 内容 |
|---|---|---|---|---|
| 9:05 | `cron-morning.php` | `stockbrain:run morning` | 9:00 寄り前 | 株価取得 → 機械的な損切り・利確・トレール・時間切れ → 厳しい新規だけ |
| 10:00 | 同じ | 同じ | 10:00 前場 | 同じ |
| 11:00 | 同じ | 同じ | 11:00 前場 | 同じ |
| 13:00 | 同じ | 同じ | 13:00 後場 | 同じ |
| 14:00 | 同じ | 同じ | 14:00 後場 | 同じ |
| 15:00 | 同じ | 同じ | 15:00 引け前 | 同じ |
| 9:30–11:20 と 13:10–15:30 の 10 分ごと（10:00 / 11:00 / 13:00 / 14:00 / 15:00 を除く） | `cron-quotes.php` | `stockbrain:run quotes` | 株価更新 | 保有の株価を更新。+2% で損切りを建値へ、+8% でトレールを武装。評価は書かない。下の条件のときだけ morning を追加。11:30–12:50 は起動しない |
| 上の株価更新で線を跨いだとき | （quotes の中） | 同じプロセスで `morning` | `10:20 追加判断` のように開始時刻 | 定時 morning と同じ売買。Gemini もその 1 回 |
| 16:00 | `cron-close.php` | `stockbrain:run close` | 16:00 引け後 | 株価取得 → 評価損益を記録。新規の売買はしない |

追加 morning を足すのは、その口座の保有が今回の株価ではじめて次のどれかを満たしたとき。

- 現在値が損切り以下
- トレール武装済みで、高値から -3%
- 含み益が +3% に届き、まだ半分利確していない

足さないのは、次の定時まで 10 分以内、時間切れだけ、継続値・取得失敗、更新前からすでに線の下にあるとき。跨いでいない口座は Gemini を呼ばない。同じ 10 分で複数銘柄が跨いでも、口座あたり 1 回。

`cron-noon.php`（`stockbrain:run noon`）はコードとして残っているが、本番 cron には載せていない。

売りはコードが先に決める。Gemini は検索して、外れても小さく負けられる新規と、根拠切れの売却だけ。実際の株の発注はしない。

保有の株価は Yahoo 銘柄ページ（`finance.yahoo.co.jp/quote/3968.T`）を先に取る。落ちたらチャート API。どちらも失敗した銘柄だけ Gemini 検索。夜間 PTS は使わない。証券会社の注文 API は使わない。Yahoo も株価を見るだけ。
現在値が値幅上限（ページの値幅制限、または東証の制限値幅表）なら新規買いしない（INC003）。

画面のジョブラベルはセッション名ではなく、開始時刻（Asia/Tokyo）で付く。`morning` を 13:00 に流しても「9:00 寄り前」にはならない。定時の時台で 0〜9 分は定時の名前、それ以外の morning は「追加判断」。

## 土日

- cron は毎日動く（発火する）
- 土日は処理をスキップする
- 株価取得・AI判断・売買はしない
- DB の実行ログ（`job_runs`）も残さない

## 休場（祝日・年末年始など）

- JPX の休業日一覧（2026・2027）をコードに持っている
- 該当日は土日と同じくスキップする（株価取得・AI・売買なし、DB ログなし）
- 対象例: 敬老の日、振替休日、1/2、12/31
- 臨時休場（台風など）は未対応
- 2028年以降のカレンダーは未登録。追加が必要

## ログの場所

| 場所 | 内容 |
|---|---|
| DB `job_runs` | セッションの成否、件数、AI の判断 |
| DB `price_quotes` | 株価の採否と理由 |
| DB `trades` | 約定履歴 |
| 画面 | 直近の実行状況 |
| `docs/05_インシデント/` | 件ごとのフォルダ（報告・リカバリ・テスト記録） |

## 補足

- 土日・東証休業日はコード側でスキップ
- 実取引連携は未実装。将来の拡張対象
- 誤約定の後始末は買い取り消し `stockbrain:void-buy`、売却単価訂正 `stockbrain:correct-sell`。売却済みの誤買いはどちらも使えない。買い単価だけ直す手順は [INC002](../05_インシデント/INC002_7513AI買値の誤採用_20261009/2026-10-09_7513_取得単価リカバリ.md)。phpMyAdmin は `COMMIT` を同じ実行欄に入れる（コメントのままだと ROLLBACK される）
- 保有も新規買いも株価は同じ取得（Yahoo ページ先行、失敗時チャート、それでも失敗時だけ AI）。AI の数字では約定しない（INC002）
- 値幅上限・ストップ高の新規はコードが止める。プロンプト任せにしない（INC003）
- 保有は最大 10 銘柄。1 銘柄の金額天井は無い。株数は現金と 1% リスクと単元 100 で切る
- 売買は 100 株単位。100 株玉の +3% は半分に割れないので全株利確。既にある端株（例: ラクス残り 50）の全決済だけ例外。第2利確の目安は +6%（3%損切りなら約2R）。残りは +8% からトレール
- 株価は対象日の年が確定できない数字、前年同日の記事、25日線一覧を採用しない（`QuoteDateGuard`。INC001）。Yahoo・AI どちらもこの関門を通す
- INC003 の株価取得差分（`YahooQuoteClient`・`DailyPriceLimit`・`TradeExecutor`）は本番に上げ済み。migrate も `.env` も cron も変えない
