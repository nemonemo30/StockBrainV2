## 1. 方針

誤ったのは **売った事実ではなく、買うときに使った現在値** である。  
10:17 の機械損切りは「売った」事実としては正しい。売った値段 1,447円も Yahoo の最終約定で正しい。

| やること | やらないこと |
|---|---|
| 売却約定を残す（`side=sell` / `action=stop_loss` / 全株 / 1,447円） | 約定を消す、買い戻す、保有を復元する |
| 買い単価を 09:55 直後の実勢に直す | 新しい売り約定を足す |
| 売り実現と現金を、直した取得単価で合わせる | `void-buy` のように買いを無かったことにする |
| 買いの `reason` 末尾にリカバリ注記を残す | 誤採用した `price_quotes` 264 を消す（原因の痕跡として残す） |
| 売りの `reason` は損切りのまま | 売り単価・売り代金を触る |

`stockbrain:void-buy` は保有が残っていて、その銘柄の売りが 0 件のときだけ。7513 は 10:17 に売っているので使えない。  
`stockbrain:correct-sell` は最新売りの約定単価だけを直す。今回直すのは買い単価なので使えない。

### 訂正単価の根拠

09:55 の Yahoo 行は DB に無い。最初の実勢は 10:05 job 56 の **1,444円**（`price_quotes.id = 268`、Yahoo チャート）。  
09:55 の買いを「その直後に確認できたチャート値で買った」とみなす。訂正単価は **1,444円** とする。

売り 1,447円（10:17 Yahoo）は変えない。

## 5. 手順

phpMyAdmin はリクエスト終了で未コミットのトランザクションを落とす。  
`COMMIT` をコメントのままにすると、画面が切り替わった時点で ROLLBACK される（本件の1回目）。

**同じ実行欄に `COMMIT` まで入れて一度に流す。**

```sql
START TRANSACTION;

UPDATE trades
SET price = 1444.0000,
    amount = 144400.00,
    reason = CONCAT(IFNULL(reason, ''), '（リカバリ: 誤取得 1509.0円を実勢 1444.0円に訂正）')
WHERE id = 39
  AND code = '7513'
  AND side = 'buy'
  AND price = 1509.0000;

UPDATE trades
SET realized_pl = 300.00
WHERE id = 40
  AND code = '7513'
  AND side = 'sell'
  AND price = 1447.0000
  AND realized_pl = -6200.00;

UPDATE portfolios
SET cash = cash + 6500
WHERE id = 1
  AND cash = 538720.00;

COMMIT;

SELECT id, side, price, amount, realized_pl, executed_at
FROM trades
WHERE code = '7513'
ORDER BY executed_at;

SELECT id, cash,
       (SELECT COALESCE(SUM(realized_pl), 0) FROM trades WHERE portfolio_id = portfolios.id) AS realized_pl
FROM portfolios
WHERE id = 1;
```

`WHERE` に訂正前の数字を入れて、二重実行しても 0 件になるようにする。  
現金がすでに 545,220 円なら、このまま流してはいけない。
