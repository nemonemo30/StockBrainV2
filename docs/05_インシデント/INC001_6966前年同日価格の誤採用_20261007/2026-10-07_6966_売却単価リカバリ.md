---

## 1. 方針

誤ったのは **約定そのものではなく、約定に使った現在値** である。  
13:01 の機械損切りは「売った」事実としては正しい。売った値段だけが、前年同日記事の 810円だった。

| やること | やらないこと |
|---|---|
| 売却約定を残す（`side=sell` / `action=stop_loss` / 全株） | 約定を消す、買い戻す、保有を復元する |
| 単価を 13時台の実勢に直す | 新しい売り約定を足す |
| 代金・実現損益・現金を同じ差分で合わせる | `void-buy` のように買いを無かったことにする |
| 訂正したことが `reason` から分かるようにする | 誤採用した `price_quotes` の履歴を消す（原因の痕跡として残す） |

買いの取り消し（`stockbrain:void-buy`）とは別物。あちらは「通ってはいけない新規買い」を消して現金を戻す。こちらは **売りは売りとして残し、値段だけ実勢に合わせる**。

### 訂正単価の根拠

13:01 約定を「13時時点の価格で売った」とみなす。  
同日 13:26 の証券会社チャート（1分足）で、6966 は **始・高・安・終すべて 941円**（941 / −7 / −0.74%）。13時台は 941円近傍で推移していたため、訂正単価は **941円** とする。

取得単価 927円は画面どおり。変更しない。

画面に出ていた 13:01 の約定。これが訂正の入力である。

| 項目 | 値 |
|---|---|
| 日時 | 2026-10-07 13:01 |
| 銘柄 | 三井ハイテック（6966） |
| 区分 | 損切り・全株売却 |
| 株数 | 200 株（`shares_after = 0`） |
| 取得単価 | 927.0 円 |
| 売却単価（誤） | 810.0 円 |
| 約定代金 | 162,000 円 |
| 実現損益 | −23,400 円（−12.62%） |
| 理由 | 損切り価格に到達したため、機械的に全株売却します。 |

検算（訂正前）:

```
実現損益 = (810 − 927) × 200 = −117 × 200 = −23,400
約定代金 = 810 × 200 = 162,000
```

## 3. どのテーブルを触るか

コマンドはトランザクション内で、次の3か所だけ更新する。  
行の追加・削除はしない。

### 3.1 直す（UPDATE）

| テーブル | 対象行 | 直す列 | 直し方 |
|---|---|---|---|
| `trades` | 当該ポートフォリオの 6966 最新売却 1件 | `price` | 810 → **941** |
| | | `amount` | 162,000 → **188,200**（941 × 200） |
| | | `realized_pl` | −23,400 → **+2,800**（(941 − 927) × 200） |
| | | `reason` | 末尾に `（リカバリ: 誤取得 810.0円を実勢 941.0円に訂正）` を足す |
| `portfolios` | 現行ポートフォリオ 1件 | `cash` | **+26,200**（188,200 − 162,000）。不足していた売却代金を足す |
| `portfolio_snapshots` | `trading_date = 当日` があるときだけ | `cash`, `cost_value`, `market_value`, `profit_loss`, `total_asset`, `realized_pl` | 訂正後のポートフォリオから再計算して上書き |

`trades` で **変えない列**: `id`, `portfolio_id`, `job_run_id`, `code`, `name`, `side`, `shares`, `shares_after`, `action`, `executed_at`。  
時刻は 13:01 のまま。区分は損切りのまま。全株売却のまま。

スナップショットがまだ無い（16時の引け後ジョブ前）ときは、`portfolio_snapshots` は触らない。引け後ジョブが訂正後の現金・実現損益を新規記録する。

### 3.2 触らない（意図的に残す）

| テーブル | 理由 |
|---|---|
| `holdings` | 全株売却済み。6966 の行は無い。復元しない |
| `trades`（6966 の買い） | 取得 927円の事実は変えない |
| `price_quotes` | 810円を採用した記録は障害の痕跡。消さない・書き換えない |
| `job_runs` | 13時台ジョブが損切りした事実は残す。`sell_count` も減らさない |
| `portfolio_snapshots`（当日以外） | 過去日の評価は当時の記録のまま |
| `stocks` / `budget_entries` / `market_index_quotes` | 無関係 |

現金の増減は「誤単価で入金が少なすぎた分を足す」だけなので、他銘柄の保有・約定には波及しない。

## 4. データをどう直すか

取得単価は売却行に保存していない。実現損益から逆算する。

```
取得単価 = 訂正前price − 訂正前realized_pl / 株数
        = 810 − (−23,400 / 200)
        = 810 − (−117)
        = 927
```

訂正後:

```
amount      = 941 × 200 = 188,200
realized_pl = (941 − 927) × 200 = 14 × 200 = +2,800
cash 増分   = 188,200 − 162,000 = +26,200
実現損益率  = 2,800 / (927 × 200) × 100 ≒ +1.51%
```

| 項目 | 訂正前 | 訂正後 |
|---|---|---|
| `trades.side` | sell | sell（変更なし） |
| `trades.action` | stop_loss | stop_loss（変更なし） |
| `trades.shares` | 200 | 200 |
| `trades.shares_after` | 0 | 0 |
| `trades.executed_at` | 2026-10-07 13:01 | 2026-10-07 13:01 |
| `trades.price` | 810.0 | **941.0** |
| `trades.amount` | 162,000 | **188,200** |
| `trades.realized_pl` | −23,400 | **+2,800** |
| `trades.reason` | 損切り価格に到達したため、機械的に全株売却します。 | 同文 ＋ `（リカバリ: 誤取得 810.0円を実勢 941.0円に訂正）` |
| `portfolios.cash` | （810円約定後の残高） | **+26,200** |
| `holdings` 6966 | 行なし | 行なし |

`portfolios.cash` の絶対値は、実行直前の他約定に依存する。トレースするときは **差分 +26,200** と、実行ログの「訂正しました。現金は ¥…」を突き合わせる。

当日スナップショットがある場合、`realized_pl` はポートフォリオ全売却の合計（`SUM(trades.realized_pl)`）で書き直す。6966 分だけ +26,200 ずれる。


```sql
       reason, executed_at, updated_at
```
