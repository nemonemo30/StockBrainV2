## 2. どの機能で発生したか

**新規買いの執行ガード**（`YahooQuoteClient` → `TradeExecutor::buy`）。

プロンプトにはすでに「`quote_state` が last 以外（limit_up / special_bid など）は buys に入れない」とある。顧問が 4498 を強い材料として出したこと自体は、超攻撃型の探索としては意図通りである。

壊れたのは **数字が取れたら `quote_state = last` にしたこと**。Yahoo チャート API は最終約定だけ返し、ストップ高フラグを持たない。

| 後続機能 | 2,560円で買うと |
|---|---|
| 新規買い | 値幅上限・張り付きでも約定する |
| 機械的な損切り | 始値が上限付近だと、直後に動かせない／大きく滑る |
| 評価 | 買えたことになり、本来見送りのセッションが成績に入る |

INC002 は「AI の値段を買値にした」。今回は「Yahoo の値段は正しいが、状態を last にした」。株価の入口ではなく、**状態の判定**が抜けている。

## 3. 事象の詳細

### 3.1 何が起きたか

10/22 13:00、サイバートラスト(4498) を **2,560円 × 100 株** で買った。  
朝からほぼストップ高水準（始値 2,550、高値 2,560）で、超攻撃型が食いつきやすい形だった。

### 3.2 なぜ last になったか

当時の経路:

1. 買い候補の株価は `StockPriceFetcher::fetch`（Yahoo 先行）
2. `YahooQuoteClient` が `regularMarketPrice` を取る
3. 数字があれば **常に `quote_state = last`**
4. `TradeExecutor` は `last` なら新規を通す（`limit_up` の拒否は状態依存）

2,560 は実勢として正しい。前日終値 2,060 に対する +24% も、50% 乖離関門は通る。関門が「数字の正しさ」しか見ていなかった。

### 3.3 なぜアプリは止めなかったか

`quote_state` の halt は、AI 本文に「ストップ高」と書いてあるときか、取得側が `limit_up` を付けたときだけ動く。Yahoo 経路は付けていなかった。注文直前に前日終値と制限値幅を照合する処理も無かった。

## 4. 再発防止策

打つ場所はプロンプトではなく、**注文直前の値幅判定**（AI 非依存）。株価の入口は銘柄ページを先に見る。

| 策 | 内容 |
|---|---|
| 制限値幅テーブル | 東証の価格帯から上限・下限を計算（2,060円なら上限 2,560円） |
| Yahoo 銘柄ページ先行 | `finance.yahoo.co.jp/quote/{コード}.T` の東証の値・前日終値・値幅制限・ストップ高表示。夜間 PTS は使わない |
| チャート API は予備 | ページが落ちたら `query1.finance.yahoo.com` の `regularMarketPrice` |
| Yahoo 取得時 | ページの上限または `DailyPriceLimit` で、現在値 ≥ 上限なら `limit_up` |
| 注文直前 | `TradeExecutor::buy` で再度 `if (price >= dailyLimitUp) reject`。特別買い気配の既存拒否はそのまま |

役割分担は次になる。

- AI「強い。買え」
- システム「ストップ高だから却下」
